# Rumin PC AI Agent — Windows 10 implementation plan

## Goal
Add a Windows 10 companion agent controlled from the existing Rumin Android app and, later, a browser dashboard. This is an extension of Rumin AI 3.0, not a replacement app.

## Non-negotiable compatibility
- Preserve the existing Android Home/Chat/Actions/Settings UI and all current phone-agent behavior.
- Do not modify the Gemini Live Voice service or its audio/session code as part of PC Agent work.
- Keep PC Agent isolated behind a separate module and bridge.
- Do not expose AI-provider keys, Windows credentials, or arbitrary shell execution to the phone/browser.

## Architecture
1. **Rumin Android controller** — adds a PC AI Agent entry and shows pairing state, command status, and approval prompts.
2. **Windows 10 Companion** — a separately installed, signed desktop process/service. It owns local file, application, screen-capture, and printer operations.
3. **Secure transport** — use an authenticated encrypted connection. Initial pairing uses a one-time code/QR and device identity; reconnect uses revocable device credentials. Do not use unauthenticated LAN HTTP or embed a shared secret in the APK.
4. **Task planner** — Gemini interprets natural-language intent and produces a constrained task plan. The PC Companion validates each operation against an explicit allowlist before execution.
5. **Audit and memory** — record task, requested operation, approval, result, and timestamps. Store only user-approved persistent memories.

## Delivery phases

### Phase 0 — protocol and threat model
- Define pairing, heartbeat, task, approval, result, disconnect, and revoke messages.
- Define an allowlisted command schema; reject unknown commands and oversized payloads.
- Establish authenticated encryption, replay protection, rate limits, and device revocation.
- Keep PC Agent disabled until a verified paired device exists.

### Phase 1 — safe Windows 10 companion MVP
- Installer/startup and visible tray status.
- Pair/unpair and connection diagnostics.
- Read-only system information and folder/file listing within user-selected roots.
- Open an explicitly selected application.
- No arbitrary PowerShell/cmd execution, silent file deletion, or background surveillance.

### Phase 2 — files, images, and printing
- User-selected folders only; preview before copy/move/rename.
- Image metadata and thumbnail preview.
- Print preview, printer selection, page range/copies, and explicit final confirmation.
- Destructive changes require a second confirmation and recoverable backup where possible.

### Phase 3 — screen and desktop interaction
- User-initiated screen sharing/capture with a visible indicator.
- Click/type/scroll only in an active, user-authorized session.
- Pause/stop control always available on the PC.

### Phase 4 — browser dashboard and memory
- Browser dashboard uses the same authenticated pairing and task protocol.
- Shared task history and approved memories; no raw credentials in browser storage.

## Safety rules
- Require confirmation before sending messages, printing, moving/overwriting/deleting files, installing software, or changing system settings.
- Never run arbitrary commands generated by the model.
- Limit file access to roots explicitly selected by the PC user.
- Screen capture and input control must be visible and user stoppable.
- Pairing credentials must be revocable and never committed to Git.

## Current repository observations
- The Android app is a WebView app with a JavaScript bridge named `RuminNative`.
- The current phone Agent has its own native command path and existing Accessibility integration.
- The app already separates Gemini Live Voice startup from ordinary task planning. PC Agent must not change that path.
- The current Android app has no PC pairing/transport implementation yet.

## Acceptance tests
- Existing Android Live Voice starts, speaks, stops, and reconnects exactly as before.
- A Windows 10 PC can pair once and reconnect after app/PC restart.
- An unpaired device cannot list files or execute operations.
- File browsing cannot escape user-selected roots.
- Unknown operations and arbitrary shell strings are rejected.
- Print preview is shown and printing happens only after explicit confirmation.
- User can revoke the paired phone from the PC at any time.
